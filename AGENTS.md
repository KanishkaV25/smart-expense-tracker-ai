# Project Rules

Project: Smart Expense Tracker AI

Project Description:
Smart Expense Tracker AI is a full-stack MERN application designed to help users manage personal finances intelligently through expense tracking, budgeting, analytics, and AI-powered financial insights.

The application allows users to:
- securely register and log in using JWT authentication
- manage daily expenses with categorized transactions
- monitor monthly budgets and spending trends
- visualize financial analytics through charts and dashboards
- receive AI-powered expense categorization and smart spending insights

The project is being developed with production-style architecture and clean engineering practices to simulate a real-world scalable application.

Primary Goals:
- Build a professional portfolio-grade project
- Demonstrate strong backend and frontend engineering skills
- Showcase REST API design and authentication workflows
- Implement clean UI/UX with responsive design
- Practice industry-standard development workflow
- Prepare for technical placement interviews such as TCS Digital

Key Engineering Focus Areas:
- JWT Authentication
- REST APIs
- MVC Architecture
- MongoDB Data Modeling
- React Component Architecture
- Secure Backend Development
- Scalable Folder Structure
- Clean Git Workflow
- Deployment and Production Readiness

Development Philosophy:
- Build modular and maintainable code
- Prioritize clean execution over unnecessary complexity
- Focus on interview-friendly architecture and explainability
- Implement one stable feature at a time
- Use meaningful commits and documentation

Goal:
Build a production-quality MERN stack project for placement interviews, especially TCS Digital.

Tech Stack:
- React.js
- Vite
- Tailwind CSS
- Node.js
- Express.js
- MongoDB
- JWT Authentication

Architecture Rules:
- Follow MVC pattern
- Keep backend modular
- Use clean folder structure
- Separate controllers, routes, models, middleware
- Use REST API best practices
- Add proper validation and error handling
- Use async/await consistently
- Keep code interview-friendly and readable

Frontend Rules:
- Use reusable components
- Keep UI responsive
- Use clean Tailwind utility classes
- Keep state management simple

Backend Rules:
- Use proper HTTP status codes
- Use JWT middleware for protected routes
- Use bcrypt for password hashing
- Keep routes RESTful
- Avoid overengineering

Workflow Rules:
- Implement one feature at a time
- Explain implementation before coding
- Suggest meaningful git commit messages
- Never generate unnecessary complexity

Code Quality Rules:
- Avoid deeply nested logic
- Keep functions small and reusable
- Use async/await instead of promise chains
- Keep controllers lightweight
- Separate business logic cleanly
- Use proper naming conventions
- Add comments only when necessary
- Prefer readability over clever code

Interview Preparation Context:
This project should help prepare for technical interviews.

Whenever implementing features:
- explain architectural decisions
- explain backend flow
- explain security considerations
- explain common interview questions
- explain why certain technologies are used
